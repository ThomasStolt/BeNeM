**This is the check the last two days were about.** On 2026-09-19 an Xcode **Release** install
declared `production` while holding a `development` entitlement, APNs answered
`400 BadDeviceToken`, and push died on the 13 Pro Max. The entitlement is set by the **distribution
re-sign at export**, not by the build configuration — so the archive is not evidence for the IPA
and must never be read as such.

**And the contrast, recorded deliberately:** the `.xcarchive`'s own app reads

this file exists.

**Consequence:** the `#else → production` branch in `AppDelegate.swift:132-136` is **true** for this
build, so its declaration matches its entitlement and the store build's push works. That is a

**Exported locally first, deliberately**, rather than `destination: upload` in one step. The
entitlement check has to happen **on the artefact that ships**, and it cannot if the same command
uploads it.

**And it is worse than "inconvenient": [MEASURED 2026-09-20] after `destination: upload`,
`-exportPath` contains NO `.ipa` at all.** The artefact is built, sent and discarded, so there is
no after-the-fact check available — the local export is the only copy of the shipping bytes anyone
will ever read. This is now a rule in the root `CLAUDE.md`.


The upload re-exported from the same archive with the same options, differing only in
`destination`. **That reproduction is an assumption, and it is stated rather than hidden** —
